# cleaner

Статический анализатор и очиститель Verilog / SystemVerilog кода. Сканирует
директивы препроцессора (`define`, `ifdef`, `include`, использования макросов),
находит мёртвые конфигурации и умеет создавать очищенную копию проекта, в
которой удалены недостижимые ветки и осиротевшие файлы.

## Режимы входа

`cleaner` принимает **один путь**, которым может быть одно из двух:

1. **Папка** — сканируется всё дерево (файлы с поддерживаемыми расширениями
   подхватываются автоматически).
2. **`.files` файл** — обычный текстовый файл со списком файлов, по одному на
   строку. Пути в файле резолвятся **относительно папки, где лежит сам `.files`
   файл** (пустые строки и `#` комментарии игнорируются). Используются только
   файлы с поддерживаемыми расширениями.

Пример `.files` (в `example/scr1/src/ahb_tb.files`):

```
core/pipeline/scr1_tracelog.sv
tb/scr1_memory_tb_ahb.sv
tb/scr1_top_tb_ahb.sv
```

## Сборка

```sh
make build          # собирает ./bin/cleaner
go build -o cleaner .  # либо собрать вручную
```

Требуется Go 1.26+.

## Использование

Путь (папка или `.files` файл) передаётся позиционным аргументом или через
`-dir`. Флаги идут **перед** позиционным аргументом.

```sh
# Отчёт по директивам в папке
./cleaner example/scr1/src

# Только закомментированные директивы из списка .files
./cleaner -commented example/scr1/src/ahb_tb.files

# Предпросмотр того, что изменит очистка (ничего не записывает)
./cleaner -clean out -dry-run example

# Очистить дерево папки в зеркальную выходную папку
./cleaner -clean example-clean -force example

# Очистить только файлы, перечисленные в .files
./cleaner -clean out -force example/scr1/src/ahb_tb.files
```

### Флаги

| Флаг            | По умолчанию | Описание |
|-----------------|--------------|----------|
| `-dir <path>`   | `.`          | Вход: папка или `.files` файл (позиционный аргумент имеет приоритет) |
| `-ext <list>`   | `.v,.vh,.sv,.svh,.svi,.vp,.svp` | Расширения для анализа (через запятую) |
| `-workers <n>`  | `0` (все CPU) | Параллельных воркеров при сканировании |
| `-json`         | выкл.        | Выводить JSON вместо текста |
| `-commented`    | выкл.        | Показывать только закомментированные директивы |
| `-active`       | выкл.        | Показывать только активные директивы |
| `-kind <list>`  | —            | Оставить только эти виды (define, ifdef, usage, …) |
| `-no-summary`   | выкл.        | Скрыть итоговую сводку |
| `-clean <dir>`  | —            | Записать очищенную копию в `<dir>` |
| `-force`        | выкл.        | Перезаписать выходную папку, если она существует |
| `-dry-run`      | выкл.        | Показать, что изменит `-clean`, ничего не записывая |
| `-defined <list>` | —         | Макросы, определённые вне дерева (флаги сборки); их ветки `ifdef` сохраняются |

Выходная папка по умолчанию — `<root>-clean` (например `example` → `example-clean`).

## Makefile

```sh
make build     # собрать ./bin/cleaner
make test      # прогнать unit-тесты
make vet       # go vet
make fmt       # gofmt -w .
make scan      # отчёт по директивам в DIR (по умолчанию: example)
make dry-run   # предпросмотр очистки DIR
make clean     # очистить DIR в OUT
make example   # короткая форма: очистить example/ в example-clean/
```

Переопределяемые переменные: `DIR` (папка или `.files` файл) и `OUT`
(выходная папка).

## Что делает очистка

Очистка (`-clean` / `-dry-run`) выполняется раундами, пока не перестанет
меняться что-либо:

1. **Закомментированные директивы** — строки `define`/`undef` в комментариях и
   закомментированные блоки `ifdef…endif` удаляются.
2. **Мёртвые ветки** — ветки `ifdef`/`ifndef`/`elsif`, чей макрос никогда не
   определён, вырезаются. Макросы из `-defined` (или из `config.go`)
   считаются определёнными, их ветки сохраняются.
3. **Неиспользуемые файлы** — файл удаляется, когда его никто не включает
   **и** он либо пуст (не осталось активных дефайнов), **либо** перестал быть
   включённым, потому что был удалён `include` из `define`-ветки. Модули
   верхнего уровня, которые никогда не включаются, не трогаются.
4. **Зачистка макросов** — после основного прохода имена всех удалённых
   макросов вычищаются из оставшихся файлов, включая комментарии и вхождения
   как подстрок.

### Защищённые дефайны

Имена макросов из `config.go` (`ProtectedDefines`) никогда не удаляются, даже
если не используются, а их ветки `ifdef` сохраняются. Это удобно для
документированных опций сборки, которые ожидают downstream-инструменты или
filelist'ы.

```go
var ProtectedDefines = []string{
	// "SCR1_TRGT_SIMULATION",
}
```
